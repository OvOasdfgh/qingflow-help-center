### 说明

Qingflow MCP 是一套让 AI 连接轻流、读取数据、处理待办和辅助分析的能力接口。

面向终端用户，当前最常用的是两类能力：

- `App User MCP`

- 面向日常业务使用

- `App Builder MCP`

- 面向应用配置与搭建

普通终端用户主要会使用 `App User MCP`。

### App User MCP 支持什么

#### 1. 身份与工作区

- 登录并校验当前身份
- 查看当前可访问的工作区
- 切换工作区
- 确认当前连接的环境和工作区

#### 2. 应用发现

- 查看当前用户有权限访问的应用
- 按应用名称搜索应用
- 在不知道应用编号时先定位目标应用

#### 3. 表单与数据查看

- 读取当前用户可见的表单结构
- 查看某张表有哪些字段
- 浏览记录列表
- 查看单条记录详情

#### 4. 数据新增、修改、删除

- 新增记录
- 修改记录
- 删除记录
- 写入前自动做字段和必填校验

复杂字段也支持辅助处理，包括：

- 成员字段候选人查询
- 部门字段候选部门查询
- 关联字段目标应用识别
- 附件上传与写入

#### 5. 数据分析

- 按字段做分组统计
- 查看占比、排行、趋势、汇总
- 输出更适合业务阅读的统计结果

#### 6. 待办与流程处理

- 查看当前待办
- 查看我发起的记录
- 查看已办记录
- 查看抄送给我的记录
- 查看单条待办的节点上下文
- 查看关联报表的详细数据
- 查看流程日志明细
- 执行流程动作

当前支持的流程动作包括：

- 通过
- 拒绝
- 回退
- 转交
- 催办

#### 7. 审批辅助

- 读取流程日志
- 读取关联报表详情
- 基于当前节点信息、流程历史和关联数据给出审批建议
- 在用户确认后再执行具体动作

#### 8. 文件与附件

- 上传本地文件
- 写入附件字段
- 在记录详情中读取附件信息

#### 9. 组织与通讯录辅助

- 查看成员、部门、组织结构
- 用于辅助查询和排查

说明：

- 对于成员字段、部门字段，系统默认优先使用字段候选能力
- 通讯录能力更适合作为辅助查询，不是业务字段填写的默认入口

### App Builder MCP 支持什么

这部分能力主要面向管理员、搭建者或实施同事。

#### 1. 应用和应用包读取

- 读取应用包信息
- 读取应用基础信息

#### 2. 应用配置与调整

- 表单结构规划与修改
- 页面布局规划与修改
- 流程配置规划与修改
- 视图规划与修改

#### 3. 搭建辅助

- 部分系统搭建与配置能力

### 当前更适合的使用场景

#### 普通终端用户

- 查数据
- 看详情
- 做统计分析
- 处理待办
- 辅助审批
- 填写或修改业务记录

#### 管理员或搭建者

- 读取应用配置
- 调整表单结构
- 调整流程与视图
- 做应用搭建和配置优化

### 使用建议

- 如果目标是查数据、改数据、做分析、处理待办，优先使用 `App User MCP`
- 如果目标是改应用配置、改流程、改页面、改视图，使用 `App Builder MCP`
- 待办审批建议先看节点详情、流程日志和关联报表，再决定是否执行动作

### 当前状态

Qingflow MCP 目前处于 `Beta` 阶段。

建议优先从以下场景开始：

- 只读查询
- 数据分析
- 待办查看
- 审批辅助
- 受控的数据录入与修改

### 当前安装方式

目前可以通过 npm 安装本地 CLI 包，CLI 内置了 MCP 的能力。

#### 前置条件：

- **Node.js ****>=16.16.0**
- **Python >= 3.11**

#### 安装 Qingflow Cli

```bash
npm install -g @qingflow-tech/qingflow-cli@latest 
```

### 最后

Qingflow MCP 的目标，不是把 AI 变成“万能员工”。它更现实的价值在于：

让 AI 在轻流这个真实业务环境里，真正具备可连接、可理解、可操作的能力。

从应用查找、记录读写，到数据分析、待办处理，再到部分应用配置，AI 不再只是停留在问答层，而是开始真正进入业务系统、理解业务结构，并在标准化接口之上完成更多实际工作。

目前 Qingflow MCP 仍处于 `Beta` 阶段，也欢迎更多团队基于真实场景一起体验、验证和迭代。
